## 本次自行修复：TestData 读取不到资源

- 实际文件：`Assets/Resources/ScriptableObject/TestData.asset`。
- 修正前读取键：`typeof(T).Name`，对于 TestData 即 `TestData`，缺少子目录。
- 修正后读取键：`"ScriptableObject/" + typeof(T).Name`，对于 TestData 即 `ScriptableObject/TestData`。
- 当前资源 GUID 与 `TestData.cs.meta` 匹配，攻击值 `2`，防御值 `3`。
- 用户反馈已修好，Agent 核对修正后的代码与资源路径一致；未自行运行，不补造 Console 输出。
- 基类加载失败时会创建新实例，因此错误路径可能让程序拿到默认值对象，表面上“有对象但没有配置数据”。以后排查应区分加载到资源与进入兜底创建这两个分支。

## 已澄清的知识边界

- 数据类型、Project 中的资源文件、运行时创建的实例是不同层面的对象与产物。
- 运行时实例的字段不会仅因为类型继承 ScriptableObject 就自动成为玩家存档；本项目通过 JSON 文件保存与恢复。
- 当前存档为手动按空格触发，不承诺未保存的修改下次恢复；实际存档位于 `Application.persistentDataPath`，不进仓库。
- 禁用活动对象上的组件不能阻止其 `Awake` 初始化，也不会自动注销已注册的 UI 回调；相关旧组件已在后续示例中移除。
- 泛型访问约定要求资源位于 `Resources/ScriptableObject/`，文件名与类型名一致；兜底创建得到的是新实例。
- 教学演示按明确目标复盘，用户已接受的简化不反复作为阻塞项；可选健壮性改进与本节完成条件分开记录。
